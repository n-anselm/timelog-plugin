## 0. Read this first

This plugin shows notes that have dates in their frontmatter on one continuous horizontal timeline. It is a private, single-user plugin — not published to the Obsidian community store.

**Trust order when documents disagree:**

1. `src/*.ts` and `src/styles.css` — the truth.
2. This file — verified notes and intent.
3. `README.md` — user-facing, and currently **stale** (it promises tags in popups and a "22 KB" bundle; neither is true).

**Never edit these by hand:**

- `main.js` — generated by esbuild from `src/main.ts`.
- `styles.css` (root) — copied from `src/styles.css`; Obsidian only loads the root copy.

**There is no test suite, no git repo, and no CI.** Verification is a build plus the manual checklist in §10. Do not claim a change works without running it.

## 1. Current state

### Implemented and working

- Read-only vault indexing from a configurable folder (default `Calendar`), subfolders optional.
- Start date from frontmatter (`date`, `startDate`, `start`) or a `YYYY-MM-DD` in the filename.
- End date from frontmatter (`date-end`, `endDate`, `end`) for multi-day bars.
- Tags → category → colour, with per-note `color` override and a configurable default colour.
- Horizontal view as a tab (ribbon icon and command), plus a ```` ```timeline ```` code block embed.
- Single central axis; dots for single-day events, bars for ranges.
- Month + day ruler that sheds detail as you zoom out.
- Adaptive labels: auto (hidden → vertical → horizontal), or forced.
- Cluster bubbles for nearby events; clicking one zooms 2.2× on it.
- Today marker (line + badge), optional grid lines.
- Cursor-pinned wheel zoom (1–140 px/day), drag panning with momentum, shift-wheel pan, trackpad horizontal pan.
- Toolbar: Today, ±month, ±year, category filter pills, label mode, zoom slider and ± buttons.
- Tooltip with title, formatted dates/range, relative time, category badge, description; Obsidian hover preview; click to open; right-click → open in new tab.
- Live refresh on vault create/delete/rename and metadata change (300 ms trailing debounce).
- Settings persisted to `data.json`, merged over defaults.

### Known broken / no-op

These are real code findings, not guesses. Document them as current behaviour; fixing them is optional work (§11).

| Issue | Detail |
|---|---|
| **Today marker colour is a no-op** | `settings.todayMarkerColor` is saved by the settings tab but never read when rendering. `renderTodayMarker()` does not set `--today-color`, so the marker is always the CSS fallback `#ff3333`. Minimal fix: `todayMarker.style.setProperty("--today-color", this.settings.todayMarkerColor)`. |
| **`autoScrollToToday` is never read** | The setting exists in `types.ts` and `data.json`, but `render()` always calls `scrollToToday(false)` after the first render. |
| **Embedded views leak and go stale** | `codeblock.ts` creates a `HorizontalTimelineView` with no lifecycle. Its tooltip `<div>` is appended to `document.body` and never removed, there is no vault-change refresh, and zoom/filter changes are not persisted (`onSettingsChange` is `() => {}`). |
| **`destroy()` is partial** | Cancels the animation frame and removes the tooltip. It does not remove the wheel listener or the global `window.onmouseup` handler. Harmless once the DOM is discarded, but the global handler survives and holds the old view. |
| **`COLOR_PALETTE` is dead code** | Exported from `types.ts`, imported by `settings.ts`, never used. Colour input is a free-text field. |
| **Mobile is unsupported in practice** | `manifest.json` says `isDesktopOnly: false`, but all interaction is mouse events; there are no touch or pinch handlers. |
| **Impossible dates pass validation** | `parseDate()` checks only month 1–12 and day 1–31. `2026-02-31` is stored as `2026-02-31` but `Date.UTC` rolls it into March, so position and displayed date disagree. |

### Unverified from code reading alone

`AGENT_CONTEXT.md` previously claimed `var(--interactive-accent)` cannot be used in `element.style.backgroundColor`. The code **does** assign it that way (`dot.style.backgroundColor = ev.color`, category dots), and also sets `--event-color` for CSS. The old note may be wrong or may describe an Obsidian quirk. Treat this as unverified: check in devtools before building a workaround. Do not propagate the claim as fact.

Related, and likely a genuine limitation: the code builds alpha colours by string concatenation — `` `${ev.color}33` `` for the tooltip badge background and `` `${ev.color}99` `` / `55` for glows. That produces `var(--interactive-accent)33`, which is invalid CSS, so accent-coloured events probably lose their badge tint and box-shadow while hex-coloured events keep them. Verify in devtools before "fixing"; the robust pattern is `color-mix()` or a hex fallback.

### Deferred features (intentional, not bugs)

- Vertical timeline layout.
- Keyboard navigation (arrows to pan, +/- to zoom).
- Date-range filter and title search.
- Touch / pinch support.
- Export (PNG, iCal).
- Multiple timeline panes with independent state.
- Custom marker shapes (triangle, diamond, etc.).

## 3. Architecture and data flow

```
TimelinePlugin (main.ts)
├── TimelineView (ItemView, "obsidian-timeline-view")
│     └── HorizontalTimelineView (toolbar + ruler + stage)
│           └── TimelineIndexer.getEvents(settings)
├── TimelineSettingTab
└── ```timeline``` code block
      └── its own HorizontalTimelineView + TimelineIndexer
```

### Plugin load

`onload()` → `loadSettings()` (`Object.assign({}, DEFAULT_SETTINGS, saved)`) → register view → ribbon icon `calendar-range` → command `open-timeline-view` ("Open Timeline View") → code block processor → settings tab.

`activateView()` reuses the first existing timeline leaf, otherwise creates a tab and reveals it.

### Main view lifecycle

1. `TimelineView.onOpen()` adds two header actions: `refresh-cw` ("Refresh timeline") and `crosshair` ("Jump to today").
2. Creates `HorizontalTimelineView(app, contentEl, plugin.settings, () => plugin.saveSettings())`.
3. Calls `refresh()` → `indexer.getEvents()` → `horizontalView.updateData(events, settings)`.
4. Registers `metadataCache.on("changed")` plus vault create/delete/rename → `debounce(refresh, 300, true)`, i.e. one refresh 300 ms after the last event.
5. `onClose()` → `horizontalView.destroy()`.

### Render flow

`updateData()` stores events/settings, **resets `pixelsPerDay` to `settings.zoomPixelsPerDay`**, then `render()`.

`render()`:

1. Creates the persistent DOM once: toolbar, scroll wrapper, track.
2. Attaches interaction handlers and the shared tooltip.
3. `updateToolbar()` — rebuilt from scratch each render.
4. `calculateBounds(filteredEvents)`.
5. `renderTrack()` — empties only the track and rebuilds ruler, today marker, stage and events.
6. On the very first render only: `setTimeout(() => scrollToToday(false), 50)`.

The toolbar, scroll wrapper, track element and tooltip node are never recreated on zoom or filter changes. **Keep this invariant**: it is what stops the scroll position jumping.

### Zoom flow (important side effect)

`applyZoom()` clamps to 1–140, writes `pixelsPerDay` and `settings.zoomPixelsPerDay`, then calls `onSettingsChange()`.

For the main view that callback is `plugin.saveSettings()`, which:

1. writes `data.json`,
2. calls `refreshOpenViews()`,
3. which calls `refresh()` on every open `TimelineView`,
4. which calls `updateData()` → `render()` → full toolbar and track rebuild,

and *then* `applyZoom()` continues with its own `renderTrack()` and scroll correction. So one zoom step causes a save, a full re-render and a second track render. It works, but it is the hot path to watch if zoom ever feels heavy. Embedded views pass a no-op callback, so their zoom is neither saved nor does it trigger a refresh.

### Settings and filter flow

- Any settings-tab change → `saveSettings()` → all open main views refresh. Embedded blocks do not refresh until their note is re-rendered.
- Clicking a category pill toggles it in `activeHiddenCategoryIds`, writes `settings.hiddenCategoryIds`, saves, then re-renders track and toolbar. In an embedded view the change is ephemeral.
- The toolbar label dropdown saves `labelMode` and re-renders the track only.

### Persistence caveat

`loadSettings()` is a **shallow** merge. New top-level fields get their defaults, but `settings.categories` is taken whole from `data.json`. Adding a new default category in code will not appear for an existing installation; users must add it in settings (or the save data must be migrated).

## 4. File-by-file reference

### `src/main.ts` — `TimelinePlugin`

Entry point. Registers the view, ribbon icon, command, code block processor and settings tab. Also owns `settings`, `loadSettings()`, `saveSettings()` and `refreshOpenViews()`. `onunload()` detaches timeline leaves.

### `src/types.ts`

`TimelineEvent`, `CategoryConfig`, `TimelineSettings`, `DEFAULT_CATEGORIES`, `COLOR_PALETTE` (unused) and `DEFAULT_SETTINGS`.

```ts
interface TimelineEvent {
  file: TFile;
  title: string;
  startDate: string;        // YYYY-MM-DD
  endDate: string | null;   // YYYY-MM-DD
  startTimestamp: number;   // UTC ms, start of day
  endTimestamp: number;     // UTC ms; end of day + 24h for ranges
  isRange: boolean;
  tags: string[];           // normalised, no leading #
  categoryId: string | null;
  categoryName: string | null;
  color: string;            // hex or var(--interactive-accent)
  description: string;
}
```

Default categories: Event `#event`, Project `#project`, Milestone `#milestone`, Deadline `#deadline`. Defaults in code use accent, `#6c849d`, `#779d6c`, `#ff3333` respectively. The live `data.json` currently uses `#9d6c6c` for Deadline — that is a user customisation, not a bug.

### `src/indexer.ts` — `TimelineIndexer`

`getEvents(settings)` walks `vault.getMarkdownFiles()`, filters by folder, parses each file, sorts by `startTimestamp` then longer first.

Folder matching trims surrounding slashes. Blank folder = whole vault. Subfolders on: path starts with `folder + "/"` (or equals it). Off: parent path must equal the folder.

`parseFile(file, settings)`:

1. First non-null frontmatter property from `startDateProperties`, else `\b\d{4}-\d{2}-\d{2}\b` in the basename.
2. No date → `null` (note is ignored silently).
3. Same for `endDateProperties`; no filename fallback for end.
4. Tags from frontmatter `tags` and `tag` (array or comma string) plus inline tags from `cache.tags`; leading `#` stripped.
5. Category = first **enabled** category with an exact case-insensitive tag match.
6. Colour precedence: frontmatter `color` → matched category colour → `defaultColor`.
7. `description` from `description`, else `summary`. `title` from frontmatter, else basename.

`parseDate(raw)` accepts a `Date` (via `toISOString()`) or a string beginning `YYYY[-/.]M[-/.]D`. Builds `Date.UTC(...)` and a zero-padded `YYYY-MM-DD`. It validates only ranges (month 1–12, day 1–31), not calendar validity.

Range semantics: `isRange` only when `end > start`. A same-day end date is a single-day dot. `endTimestamp` is always start + 24h for points, or end + 24h for ranges, so the final day is included in the bar.

### `src/timelineView.ts` — `TimelineView`

Thin `ItemView` wrapper. View type `obsidian-timeline-view`, title "Timeline", icon `calendar-range`. Header actions: `refresh-cw` and `crosshair` (the latter calls `scrollToToday(true)`).

The debounced refresh is created in the constructor with `debounce(fn, 300, true)`.

### `src/settings.ts` — `TimelineSettingTab`

Sections: **Folder & Source Filter**, **Date Extraction**, **Display & Appearance**, **Categories & Colors**.

Settings UI only. Category rows are a CSS grid of: enabled checkbox, colour text input (free text, no palette), name, tag, delete. Values save on `change`, not while typing. The raw DOM is used instead of Obsidian's `Setting` component for the rows. `COLOR_PALETTE` is imported but unused.

### `src/codeblock.ts`

Registers the `timeline` code block. Parses simple `key: value` lines:

- `folder` (quotes stripped)
- `zoom` (integer; **not clamped**, so `zoom: 500` produces 500 px/day even though the slider caps at 140)
- `labels` / `labelmode` (must be lowercase: `auto`, `vertical`, `hidden`, `horizontal`; values are compared case-sensitively)

Lines starting with `#` are comments. Keys are lowercased. Everything else is inherited from plugin settings via a shallow spread. Creates `div.embedded-timeline-container` (380 px tall) and a `HorizontalTimelineView` with a no-op settings callback. No cleanup and no live refresh — see §1.

### `src/views/horizontalTimeline.ts` — `HorizontalTimelineView`

The rendering engine and the file you will mostly edit. State:

- Scale: `pixelsPerDay`, `minTimestamp`, `maxTimestamp`, `totalDays`.
- Persistent DOM: `toolbarEl`, `scrollWrapperEl`, `timelineTrackEl`, `zoomSliderEl`, `tooltipEl` (on `document.body`), `isInitialRender`.
- Pan physics: `isDragging`, `startX`, `scrollLeft`, `lastMouseX`, `lastMouseTime`, `panVelocity`, `animFrameId`.
- Filter: `activeHiddenCategoryIds`.

Methods: `render`, `renderTrack`, `renderRuler`, `renderTodayMarker`, `renderTimelineLineAndEvents`, `updateToolbar`, `applyZoom`, `scrollToToday`, `panByDays`, `showTooltip`, `showClusterTooltip`, `getRelativeTimeMessage`, `formatDateForDisplay`, `setupInteractionHandlers`, `destroy`.

### `src/styles.css` (copied to root `styles.css`)

All styling. See §8 for the class map. The two files are currently identical; keep them that way.

## 5. Behaviour specification

### Scale and bounds

The axis always covers **at least** January 1 of last year through December 31 of next year. If events exist outside that window, the range expands to one year before the earliest event year and one year after the latest. `totalDays` includes both endpoints.

Position of a date: `(timestamp - minTimestamp) / 86400000 * pixelsPerDay`.

Single-day dot centre: `startX + pixelsPerDay / 2`. Range bar: left = `startX`, width = `max(1, round((end - start) / day)) * pixelsPerDay`. Today marker: start-of-day offset + `pixelsPerDay / 2`.

### Ruler

Month row (26 px) and day row (40 px), sticky at the top of the track.

| `pixelsPerDay` | Month label | Day ticks | Day number | Weekday | Grid lines (if enabled) |
|---|---|---|---|---|---|
| `< 5` | Year on January only | — | — | — | Month-start line (`day === 1`) |
| `5–11` | Year on Jan, short month otherwise | Month-1st tick + month letter | — | — | Month-start line |
| `12–17` | Short `Jan '26` | Month-1st tick + month letter | — | — | Month-start line |
| `18–21` | Short | Day tick, no text | — | — | Monday lines |
| `22–29` | Short | Day tick | Number | — | Monday lines |
| `30–34` | Short | Day tick | Number | — | Monday lines |
| `35–45` | Full `January 2026` | Day tick | Number | — | Monday lines |
| `46–64` | Full | Day tick | Number | `Su`…`Sa` | Monday lines |
| `≥ 65` | Full | Day tick | Number | Weekday | Monday lines |

Weekend day columns get a subtle background. Grid lines start below the ruler (`top: 64px` in CSS).

Day ticks are also drawn on the central axis (`.timeline-day-tick-mark`): 1×18 px in `--text-muted`, centred on each day, from 18 px/day upward. At ≥65 px/day — the same threshold where auto labels go horizontal — they grow to 24 px tall so events are easier to align with the ruler above. Do not use `--background-modifier-border` here: it resolves to `--color-base-30` and makes 1 px marks effectively invisible.

### Labels

Effective mode: the setting, or for `auto`: **hidden** below 30 px/day, **vertical** at 30–64, **horizontal** at ≥ 65.

Labels hang from stems on a three-tier ladder: 28, 64 and 100 px. Side alternates above/below by item index in the render loop (clusters and single events share the counter). A tier is reused only when the previous label on that side is at least 28 px away (vertical) or 100 px away (horizontal); otherwise the other side is tried, then the last tier. Range bars anchor their label near their left edge (`min(20px, width/2)`).

Bar thickness and inline titles:

- `≥ 55` px/day: 18 px bar, title shown if the bar is wider than 50 px and labels are not hidden.
- `30–54`: 8 px bar, no title.
- `< 30`: 4 px ribbon, no title.

### Clustering

Events are considered in chronological order and merged into the immediately preceding cluster when:

- the centre is within **22 px** of that cluster's centre,
- the event is not a range longer than 40 px at the current zoom,
- the previous cluster is not a range.

Merging is chained, and the cluster centre is the running mean of member centres. A cluster renders as an accent-coloured numbered bubble (`.timeline-cluster-dot`); the event colours are used only as dots in the cluster tooltip. Long bars never collapse into a cluster.

Hover → "N Events Merged" list (each row opens its note). Click → `applyZoom(min(140, round(pixelsPerDay * 2.2)))` centred on the cluster.

### Today marker

Rendered only if `showToday`. Structure: `.timeline-today-marker` positioned at the day centre, containing `.timeline-today-badge` ("TODAY") and `.timeline-today-line`. The line fades at both ends via a CSS mask (solid 33–67%). Colour comes from the CSS variable `--today-color` (fallback `#ff3333`); the setting is not wired up (§1).

### Tooltip

One `div.timeline-floating-tooltip` per view, `position: fixed`, `z-index: 9999`, appended to `document.body` and positioned near the cursor with viewport-edge flipping.

Contents, in order: title; date or `start → end` (`Nov 10, 2026` format); relative time; category badge (only when categorised, tinted with the event colour); description (only when present). **No tags and no calendar icon** — deliberately removed by the user.

Hovering an event also fires Obsidian's `hover-link` event (source `timeline-view`, `sourcePath` = file path) for the native page preview.

Relative time is computed in local calendar days then in UTC:

- ongoing range → `Ongoing (ends today|tomorrow|in N days)`
- `Today`, `In 1 day (Tomorrow)`, `1 day ago (Yesterday)`
- otherwise years/months/days, at most two units: `In 3 months`, `2 years, 1 month ago`

The month arithmetic borrows days from the previous month and is approximate at month ends; acceptable for display.

### Interactions

| Input | Result |
|---|---|
| Drag on empty track | Pan; 1.3× movement multiplier |
| Release while moving | Momentum: velocity × 16, capped ±55 px/frame, friction 0.94, stops below 0.25 px/frame |
| Wheel | Zoom at the cursor; guarantees at least ±1 px/day so it cannot stall at 1 |
| Shift + wheel | Pan sideways (`deltaY || deltaX`, ×1.4) |
| Trackpad horizontal | Pan (`|deltaX| > |deltaY|` and > 2) |
| Click dot/bar/label | Open note in current leaf |
| Right-click event | Menu: "Open note in new tab" |
| Hover event | Tooltip + hover preview |
| Click cluster | Zoom 2.2× centred on it |
| Today button | Smooth-scroll today to centre |
| ± Month / ± Year | Smooth-scroll by 30 / 365 days |
| Label dropdown | Change effective label mode |
| Zoom −/+ | −6 / +8 px/day, but −1 / +2 below 10 px/day |
| Category pill | Show/hide that category |

Mouse-down is ignored when it starts on an event or cluster (so clicks still work). `window.onmouseup` is assigned directly, not added as a listener — the last view wins. `destroy()` does not clear it.

## 6. Settings reference

Stored in `data.json` at the plugin root. Persisted through `loadData`/`saveData`.

| Field | Default | Effect | Status |
|---|---|---|---|
| `folder` | `"Calendar"` | Folder to scan; blank = whole vault | works |
| `includeSubfolders` | `true` | Recursive scan | works |
| `startDateProperties` | `["date","startDate","start"]` | Priority order for the start date | works |
| `endDateProperties` | `["date-end","endDate","end"]` | Priority order for the end date | works |
| `categories` | 4 defaults | Tag → name/colour mapping | works |
| `defaultColor` | `var(--interactive-accent)` | Colour for uncategorised events | works |
| `todayMarkerColor` | `"#ff3333"` | Intended marker colour | **no-op** |
| `zoomPixelsPerDay` | `40` | Initial zoom; also updated live by zooming the main view | works |
| `labelMode` | `"auto"` | `auto` / `vertical` / `hidden` / `horizontal` | works |
| `showToday` | `true` | Render the today marker | works |
| `showGrid` | `true` | Monday lines ≥15 px/day, month-first lines below | works |
| `autoScrollToToday` | `true` | Intended to control the initial scroll | **never read** |
| `hiddenCategoryIds` | `[]` | Persisted filter state from the pills | works (main view only) |

Category semantics: `enabled: false` stops the category being matched, so its events fall back to `defaultColor` and lose their badge — it does **not** hide them. Use the toolbar pill (or `hiddenCategoryIds`) to hide. Deleting a category only removes the mapping.

Hidden-category filtering applies only to events with a matching `categoryId`; uncategorised events are always visible.

## 7. Event note format and category matching

```yaml
---
title: "My Event"           # optional; falls back to filename
date: 2026-11-10            # required (or put YYYY-MM-DD in the filename)
date-end: 2026-11-15        # optional; makes a bar
tags:
  - event                   # matches the Event category
description: "Shown in the hover popup"
color: "#ff9900"            # optional per-note override
---
```

- Date formats: `YYYY-MM-DD`, `YYYY/MM/DD`, `YYYY.MM.DD`. Leading year required.
- The filename fallback only supplies a start date.
- Tags may be frontmatter `tags`/`tag` (array or comma string) or inline `#tags` in the note body.
- Matching is exact after lowercasing and stripping `#`; the first enabled category in list order wins, so ordering matters if tags overlap.
- Notes without a parseable start date are skipped entirely.
- This convention is shared with the user's **Linear Calendar** plugin (`date`, `date-end`, `#event`).

Code block options (all optional, keys case-insensitive, label values must be lowercase):

````markdown
```timeline
folder: Projects
zoom: 60
labels: vertical
```
````

## 9. Gotchas and lessons learned

| Area | Lesson |
|---|---|
| Persistent DOM | Never rebuild toolbar/scroll wrapper/track on zoom; empty only the track. Scroll position is preserved by design. |
| Zoom | Guarantee at least ±1 px/day per wheel step or zoom gets stuck at 1. |
| Zoom side effect | Zooming the main view saves settings and re-renders all open views before the track re-render. Keep that in mind before adding work to `render()`. |
| Settings merge | `Object.assign` is shallow; `categories` is not merged with defaults. |
| `var()` in inline styles | Code assigns `var(--interactive-accent)` to `style.backgroundColor` for dots/category dots. The old claim that this cannot work is **unverified**; check devtools before "fixing". |
| Theme colours | Use hex in JS where a concrete value is read back or concatenated (e.g. `` `${color}33` ``), and CSS variables for pure styling. |
| `window.onmouseup` | Assigned, not registered. It overwrites other handlers and is not cleaned up in `destroy()`. Acceptable while only one view exists; revisit if multiple timelines become possible. |
| Ruler layout | Use flex centring and `gap`; adding `position: relative` to day labels causes overlap. |
| Code block values | `labels` values are compared case-sensitively and zoom is not clamped. |
| Embedded views | No cleanup hook, no live refresh, no persistence. Adding a `timeline` code block to many notes leaks one tooltip per block until the note closes. |
| Date parsing | Only range-checks month/day; impossible dates roll over in `Date.UTC` while keeping the original string. |
| CSS copy | A CSS edit that is not copied to the root is invisible in Obsidian. Check with `diff -q`. |
| Generated files | `main.js` is minified in production; never patch it. Rebuild after every TS change. |

## 11. Decision log

Why things are the way they are. Update this when a decision changes.

- **UTC day arithmetic** — every date is `Date.UTC(y, m, d)` so DST and local time cannot shift an event by a day. Display still uses the user's calendar.
- **End date is inclusive** — `endTimestamp` adds 24 h so a range ending on the 15th covers the whole 15th.
- **One continuous axis** — the user explicitly chose a single line with dots/bars over lanes or a vertical list.
- **Persistent DOM** — zoom re-renders only track contents to keep the scroll position stable.
- **Zoom range 1–140 px/day** and everything (ruler detail, labels, bar thickness, clustering) adapts to it rather than exposing separate controls.
- **Cursor-pinned zoom** — the day under the pointer stays under the pointer.
- **Heavy momentum** — friction 0.94 and a ±55 px/frame cap were tuned by feel; the user wants the timeline to feel weighty.
- **Clusters zoom instead of expanding in place** — keeps the axis clean when zoomed out; 2.2× is enough to split one bubble per click.
- **Popups are minimal** — tags and the calendar icon were deliberately removed; keep title, date, relative time, badge, description.
- **Zero runtime dependencies** — only `obsidian` is external; everything else is bundled. KISS is an explicit user preference.
- **CSS stays outside the bundle** — Obsidian's convention; hence the manual copy step.
- **Linear Calendar compatibility** — `date` / `date-end` / `#event` conventions are shared with another installed plugin.

## 14. User preferences and design principles

- **Aesthetic:** polished, clean, minimal chrome; no clutter.
- **Accents:** UI elements use `var(--interactive-accent)`, never hardcoded blue/purple.
- **Today marker:** bright red by default and intentionally prominent; the colour is meant to be configurable.
- **Popups:** no tags, no calendar emoji/icon; title, date, relative time, category badge, description only.
- **Feel:** heavy momentum panning with slow deceleration.
- **Formats:** display dates as `Nov 10, 2026`; relative time as `3 years, 2 months ago`, `In 5 days`, `Ongoing (ends in 3 days)`.
- **Engineering:** KISS, no unnecessary dependencies, defensive handling of malformed frontmatter, UTC-stable dates.
- **Scope:** horizontal layout is the priority; vertical, keyboard, touch, export and multi-pane are deferred (see §1).
